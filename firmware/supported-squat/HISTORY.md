# Supported squat

機体と脚の全重量を外部で支える初回屈伸試験。自立・歩行用ではない。

## Build / upload

```sh
/Users/haruta/.platformio/penv/bin/pio run -e supported-squat
# サーボ用電源を外し、NEXUSのDISCONNECT後に実行
/Users/haruta/.platformio/penv/bin/pio run -e supported-squat -t upload
```

NEXUSにUSB接続してMOTIONを開くと、ファームウェアの状態受信後に屈伸画面へ切り替わる。
画面の準備完了はESP32からの応答に基づく。5秒でARM失効。起動時は移動もトルクONも送らない。

## Commands

1. 支持を維持して`SQUAT DOWN`（4台OFF確認 → 屈伸目標設定・読戻し → 4台ON確認 → 移動開始）。現在位置を目標にする準備はない。
2. `squat_state_down`を確認し、姿勢・リンク・音を目視確認する。
3. `SQUAT ARM UP` → 5秒以内に`SQUAT UP`。
4. `squat_state_complete`で1往復終了。保持は継続する。

`DISARM`は未実行の準備だけを取り消す。移動や保持を停止する命令ではない。
`SQUAT STOP`は平面リンク4台を同時にトルクOFFにし、FAULTに固定する。

## Limits and fault behavior

- ID 12,13,22,23の中立は595,0,899,158、屈伸候補は712,173,1000,306。Yawは書き換えない。
- DOWN前は中立値との比較・準備時の±3 raw判定を行わない。支持と開始姿勢の目視確認は操作者が担当。通信・計測値の有効性は残す。DOWN前は保持ONに伴うmoving=1を正常として許可し、準備確認・ARM・DOWN開始のいずれでも停止待ちを要求しない。停止確認は動作後の到達とUP前で行う。UPの開始確認と到達判定は±17 rawを維持。
- 拒否時はIMU・応答・位置/停止・トルクの理由をログに出す。
- DOWNは支持した現在位置から開始。UPは同一セッションでDOWN到達済みかつ屈伸候補付近でのみ許可。
- 6台の有効な応答、500 ms以内のIMU更新、4台のトルクONを開始前に検査。
- 正常な応答でも、報告電圧が4〜7.4 V外、温度が60℃以上、位置やmovingが不正なら試験を許可しない。温度60℃は本試験の保守的中止値。
- 1500 ms/速度40の同期命令。±17 raw（約5°）内かつ停止を100 ms周期で3回確認して到達。
- 0/1023境界を近道とみなさない。raw 1023から0への位置指示を許容判定で正当化しない。
- 準備の部分失敗、2000 ms未到達、準備後の保持中・移動中の通信・計測異常、IMU鮮度切れ、STOPで4台を同期トルクOFF。その後に解除レジスタを読み、未確認なら外部電源切断をログで要求する。
- 時間切れは通常ループで監視する。I2CやCPU全体のハング、配線断、電源故障に対する独立したハードウェア停止装置ではない。
- 正常到達時は元の目標を保持する。許容幅を広げても内部の追従不感帯は変わらず、音の解消を保証しない。
- FAULT後にGUIから復帰やトルクONはできない。電源を切り、原因と支持を確認して再準備する。
- リセット時はセッション状態が消えるが、外部給電中のサーボの保持は消えない。緊急停止は外部サーボ電源の切断。

## v11：手動リセット・到達誤差記録（未書込み）

## 2026-10-10: 初期姿勢から直接立つ

## v18: 直立停滞の切り分け

動作中は500msごとに4軸の目標・実測・ReadLoadの符号付き出力値・有効性・電圧・温度をsquat_output_*へ出す。既存FeedBackのキャッシュを使い、周期的な診断のためのUART読取りは追加しない。出力表示はモーター駆動の指標で、実測トルク・電流ではない。valid=0の値は判断に使わない。
STATUSは従来の角度/トルク制限に加え、設定レジスタ19/21/22/23/24/26/27/37/38/39を読み取る（設定変更なし）。停止中に要求する。位置目標、移動時間、速度、到達判定、解除条件は変更していない。
出力が高いまま位置が止まるなら負荷/抵抗/供給を疑い、出力が低い場合は制御設定や保護作動を検討する。これだけで機械原因を確定せず、支持条件を揃えた比較を行う。

## v19: 膝を先に伸ばす順序比較

UPを2段階に分ける。開始時は4台OFFと直立目標書込み/読戻しを確認し、13・23のみON（12・22はOFF確認）。両膝がそれぞれ実効目標±17 rawに入り、500ms継続したら、直立目標と1500msを再送/確認して12・22をONにする。その後4台が±17 rawで500ms継続すると全台OFF。13の実効目標20は変更していない。速度40、DOWNの動き、関節範囲、STOP保持、RELEASE、通信失敗時の解除も維持する。上側OFFで自重移動しないという操作者の確認を前提に、機体支持で1往復のみ比較する。

ログは squat_up_phase_knees_13_23 → squat_result_up_knees_* → squat_up_phase_upper_12_22 → squat_result_up_* → squat_target_reached_released。前段で膝が届かなければ上側は動かさない。到達待ちの時間打切りは追加していないため、停滞/発熱時は手動RELEASE。膝の出力は上側段階もONで保持し、途中での自動解除はしない。仮説の検証であり、この順序が機械的に有利かは実機ログで判断する。

## v21: 診断情報の取り漏れ対策

全6台の各フィードバックにspeed_raw/output_raw/current_register_raw/feedback_result/servo_error/protocol_error/read_msを追加。失敗時はキャッシュの位置/電圧/温度を出さず、UART読取り失敗・サーボエラー・値の無効を区別する。これらは追加UART要求ではなく既存FeedBackとキャッシュから取得。current_register_rawは未検証の生レジスタであり、SCS0009の実測電流やmAとして扱わない。STATUSでモデル識別のレジスタ3とファームウェア識別を再送する。

collectorは接続時に読み取り専用STATUSを自動送信し、版と設定を保存する。新しいフィールドはraw JSONにそのまま残り、旧UI用parsedには追加しない。旧UIへの機能追加や表示変更はない。周期的出力/statusは通常の250ms/100件バッチにまとめ、エラー・コマンド等は即時保存のまま。

## v23 自動足踏み1周

Motionの「足踏み」→「足踏みを1周」は`STEP AUTO`を送る。
初期直立→左足上げ→直立→右足上げ→直立の5段階を、
各段階の到達・500ms継続・解除確認後に自動で進める。最後は全4台解除。
途中STOPは現在位置固定し連続動作を破棄。RELEASE・異常も連続動作を破棄。
再開には新しくボタンを押す。回数は1周固定で無限反復なし。
段階ログは`step_auto_phase_*`、完了は`step_auto_complete_released`。
